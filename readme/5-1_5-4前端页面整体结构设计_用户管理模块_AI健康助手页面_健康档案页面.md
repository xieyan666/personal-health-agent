# Personal Health Agent 开发记录

> 本文档根据当前仓库代码、迁移文件和运行配置整理（更新时间：2026-08-25）。未在代码中发现的能力均标注为 TODO / planned，不代表已实现。

## 1. 项目整体架构

当前项目是 Electron 桌面端 + React/Vite 前端 + FastAPI 后端。前端通过 Axios 请求 `/api/v1`，后端使用 SQLAlchemy AsyncSession 访问 PostgreSQL；Redis、Qdrant、MinIO 由 Docker Compose 提供。模型网关位于 `backend/app/model_gateway`，当前支持 `FakeChatProvider` 和 `DeepSeekChatProvider`。

主要调用链：

```text
Electron
  └─ React/TypeScript 页面
       └─ Axios request.ts（JWT Bearer）
            └─ FastAPI router
                 └─ Service / Repository
                      ├─ PostgreSQL（用户、会话、健康数据、AgentRun）
                      ├─ Qdrant（向量检索）
                      ├─ MinIO（文件存储）
                      └─ model_gateway → Fake/DeepSeek
```

后端入口为 `backend/app/main.py`，统一注册 CORS、异常处理及 API routers。数据库连接和基础设施配置位于 `backend/app/core`；JWT 与密码安全位于 `backend/app/auth`。

## 2. 前端整体结构记录

前端根目录为 `frontend`，主要目录：

```text
src/
├─ api/              Axios API 封装
├─ components/layout/ MainLayout、Header、Sidebar
├─ pages/
│  ├─ Login.tsx
│  ├─ employee/      EmployeeHome、HealthAssistant、Profile 等
│  └─ admin/         AdminHome、UserManagement、EmployeeManagement
├─ router/           路由与 RouteGuard
├─ store/            authStore、userStore（Zustand）
└─ styles/           全局、助手和档案页样式
```

### 主要页面

| 页面 | 文件 | 作用 | 主要接口 |
|---|---|---|---|
| 登录 | `frontend/src/pages/Login.tsx` | 登录、保存 JWT、按角色跳转 | `/api/v1/auth/login` |
| 员工首页 | `frontend/src/pages/employee/EmployeeHome.tsx` | 员工工作台占位与入口 | 当前以页面结构为主 |
| AI 健康助手 | `frontend/src/pages/employee/assistant/HealthAssistant.tsx` | 会话列表、聊天、上下文和 Agent Trace | `/api/v1/health-agent/chat`、`/chat/stream`、Conversation API |
| 健康档案 | `frontend/src/pages/employee/Profile.tsx` | 基本信息、当前指标、睡眠/运动/心率趋势；只展示健康事实 | `/api/v1/health/profile`、`/health/trends`、`/health/summary` |
| 健康风险 | `frontend/src/pages/employee/Risk.tsx` | 风险评分、规则风险因素、风险趋势展示、AI 风险解释报告 UI | `/api/v1/health/risk` |

## 3. 用户管理模块

### 前端

`UserManagement.tsx` 提供员工列表、关键词查询/联想、分页、创建和编辑，以及角色下拉、启用/禁用、删除确认、重置密码确认。`adminUsers.ts` 和 `users.ts` 封装请求，路由权限由 `router/guard.tsx` 与后端 JWT/RBAC 共同保证。

### 后端 API（以代码注册路径为准）

- `POST /api/v1/auth/login`、`GET /api/v1/auth/me`
- `GET/POST/PUT/DELETE /api/users`（`main.py` 同时以 `/api/v1/admin` 和 `/api` 挂载 RBAC 用户 router）
- `PUT /api/users/{id}/role`
- `PATCH /api/users/{id}/status`
- `PUT /api/users/{id}/reset-password`
- 用户查询支持关键词、拼音字段及员工管理过滤逻辑（具体参数以 `backend/app/api/routes/rbac_users.py` 为准）。

密码只保存 `users.password_hash`，由 `backend/app/auth/security.py` 生成和校验 bcrypt hash。JWT payload 与解析位于 `backend/app/auth/jwt.py`；`get_current_user` 查询数据库用户并执行状态校验，禁用用户不能继续使用旧 token。

### 数据库

`users`（`backend/app/models/user.py`）包含 UUID `id`、`username`、`display_name`、`name_pinyin`、`department`、`department_id`、`position_id`、`company_id`、`role`、`email`、`password_hash`、`status`、时间戳及外部认证字段。RBAC 组织模型在 `models/rbac.py`、`models/organization.py`：`companies`、`employees`、`roles`、`permissions`、`role_permissions`、`departments`、`positions`。

## 4. AI 健康助手模块

### 前端

路径：`frontend/src/pages/employee/assistant/HealthAssistant.tsx`。页面包含最近会话、聊天消息、输入框、健康上下文和执行轨迹。接口封装在 `src/api/healthAgent.ts`、`src/api/conversations.ts`（如当前版本存在）。请求携带当前登录 JWT，用户消息和 assistant 回复由后端会话接口返回并展示。

### FastAPI

路由：`backend/app/api/routes/health_agent.py`，由 `main.py` 以 `/api/v1` 注册：

- `POST /api/v1/health-agent/chat`：同步健康问答。
- `POST /api/v1/health-agent/chat/stream`：SSE 流式返回 `message_delta`，结束时保存 assistant message。

请求模型位于 `backend/app/schemas/health_agent.py`，核心字段是 `message` 与可选 `conversation_id`。接口通过 `get_current_user` 获取身份，不接受前端伪造 `user_id`；会话和消息写入 `conversations`、`messages`，会话归属必须匹配当前用户。

### Agent、Tool 与模型

通用 Agent 执行器为 `backend/app/agent/runtime.py` 的 `AgentRuntimeService`，负责 Agent、ModelConfig、Provider、Conversation、Message、AgentRun 校验及工具循环。内置工具注册和执行位于 `backend/app/tools/registry.py`、`executor.py`、`builtin.py`；已存在 `health_profile.py`、`health_trend.py`，并有 MCP 适配器（`tools/mcp.py`、`backend/app/mcp`）。

模型网关 `backend/app/model_gateway/chat.py` 提供统一 `ChatProvider`、`ChatResult`、流式事件及 provider factory；DeepSeek 使用 `secret_ref=env:DEEPSEEK_API_KEY`，不会把 key 放入数据库参数或前端。`llm_service.py` 是健康助手目前复用的服务封装。健康助手当前调用链为：

```text
当前用户 + message
 → health_agent router
 → Health Profile context tool
 → LLMService / DeepSeekChatProvider
 → Message 持久化
 → answer 或 SSE delta
```

当前代码已具备 RAG、Tool Calling、MCP 和 Multi-Agent runtime 基础；健康助手页面的业务路由仍以现有 router/runtime 实现为准。Sleep Agent、Nutrition Agent、Fitness Agent 等专用健康 Agent 未在当前健康助手 router 中形成独立路由时，标记为 planned，不在本文档中假设已完成。

## 5. 健康档案模块

页面：`frontend/src/pages/employee/Profile.tsx`，样式：`profile.css`、`styles/profile-layout.css`。页面展示：

- 基本资料：年龄、性别、身高、体重、BMI；用户账号从当前用户身份显示。
- 当前指标：睡眠、运动、心率等。
- 健康趋势：睡眠、运动、心率 ECharts 图表，支持近 7/15/30/60 天范围，前端根据接口数据更新展示。

健康档案不再展示健康风险评估或 AI 健康摘要；风险判断、风险因素和风险建议统一在 `/employee/risk` 页面展示。AI 健康摘要组件文件仍保留在仓库中，但当前不在健康档案页面挂载。

### 数据来源

后端模型分别为 `health_profiles`、`sleep_records`、`exercise_records`、`heart_rate_records`（`backend/app/models/health_profile.py`、`health_records.py`）。趋势 API 为 `backend/app/api/routes/health_data.py`；规则分析由 `services/health_analysis_rules.py` 和 `services/risk_assessment.py` 完成，风险记录保存到 `risk_assessments`。AI 摘要模型为 `health_summaries`，服务为 `services/health_summary.py`，调用已有 LLM 封装生成摘要 JSON；前端 adapter 负责把兼容格式转换成卡片视图模型。

## 6. 数据库设计总览

当前 SQLAlchemy 模型/迁移覆盖：

| 表 | 用途 |
|---|---|
| `users` | 认证用户、角色、状态和组织关联 |
| `companies`, `employees` | 企业与员工扩展资料 |
| `roles`, `permissions`, `role_permissions` | RBAC 字典和关联 |
| `departments`, `positions` | 部门岗位字典 |
| `agents`, `model_providers`, `model_configs` | Agent 与模型配置 |
| `conversations`, `messages` | 会话及用户/assistant 消息 |
| `agent_runs` | Agent 执行状态、token、输出和错误 |
| `tools` | 内置/MCP 工具定义 |
| `knowledge_bases`, `documents`, `document_chunks` | 知识库、文档、Chunk |
| `health_profiles` | 用户健康档案 |
| `sleep_records`, `exercise_records`, `heart_rate_records` | 可穿戴/健康趋势记录 |
| `risk_assessments` | 规则风险评估结果 |
| `health_summaries` | AI 健康摘要 JSONB |
| `audit_logs` | 审计记录 |

迁移目录为 `backend/alembic/versions`。当前可见迁移包括初始 schema、Chunk、认证/RBAC/组织字典/拼音、健康档案、健康记录、风险评估和健康摘要；未在迁移文件中新增本文档之外的表。

## 7. 当前技术栈

- 前端：React 19、TypeScript、Vite、Electron 31、Ant Design、Axios、Zustand、ECharts。
- 后端：FastAPI、Pydantic schemas、SQLAlchemy AsyncSession、Alembic。
- 基础设施：PostgreSQL 16、Redis 7、Qdrant 1.15、MinIO，配置见 `docker-compose.yml` 与 `backend/app/core/config.py`。
- AI/Agent：DeepSeek OpenAI-compatible Chat Completions、统一 ChatProvider/ChatResult、Fake provider 测试、Tool Registry/Executor、RAG Retrieval、stdio/HTTP MCP 基础、Multi-Agent runtime 代码。
